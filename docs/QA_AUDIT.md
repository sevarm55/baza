# Аудит продукта

Прогон по живому продукту: веб-кабинет, приложение, API, база. Не список
рекомендаций — что проверено, что сломалось, что починено и чем это
теперь закрыто от повторения.

Дата прогона: 15 августа 2026. Ветка `claude/carwash-product-audit-626987`.

---

## Как устроен продукт

```
Веб-кабинет                     Приложение (iOS)
app/owner/*, app/work           ios/Tetr/Features/*
     │ Server Actions                │ Bearer JWT
     │ app/actions.ts                │ ios/Tetr/Core/API.swift
     ▼                               ▼
                app/api/v1/*  ← общие маршруты
                     │
         lib/orders · lib/queries · lib/payroll · lib/expenses
                     │  ← вся арифметика денег живёт здесь
                     ▼
              Drizzle ORM  ·  lib/db/index.ts
                     │
        DATABASE_URL задан → Postgres (сервер)
        не задан            → PGlite, файлы в .data/
```

Вход: `lib/auth.ts` — cookie `bz_session` в вебе, access/refresh в
приложении, оба на одном HS256-секрете.

Деньги считаются в одном месте и целыми числами: `lib/money.ts`.
Клиенты повторяют результат, а не формулу — приложение получает `earned`
готовым и никогда не умножает само.

## Окружения

| | до аудита | после |
|---|---|---|
| Xcode, кнопка Run | **боевой сервер** `tetrin.pro` | `localhost:3100` |
| `npm run dev` | любая база из `.env.local`, включая боевую | только своя, иначе отказ |
| `npm run e2e` | пишет только на порту 3100, иначе молча 4 проверки из 95 | пишет на любом localhost |
| `npm run smoke` | база в памяти | без изменений |

Обход замка, когда чужая база нужна осознанно:
`TETR_ALLOW_REMOTE_DB=1 npm run dev`. Адрес сервера для приложения —
`TETR_API` в схеме Xcode (`ios/project.yml`), значение `prod` означает бой.

## Исправлено

### S1 · Ставка сотрудника обнулялась молча

`PATCH /api/v1/staff/{id}` с телом `{"percent": null}` отвечал
`200 сохранено` и записывал ноль: `Number(null)` — это 0. Человек
продолжал мыть машины, а зарплата переставала начисляться. Заметить это
можно было только в день расчёта, когда пересчитывать уже нечего —
снимки в записях легли с нулём.

Второй половиной той же ошибки был отказ на частичной правке: маршрут
требовал `name` и `percent` вместе, и «переименовать человека» без
ставки означало ту же ноль-ставку.

Починено в `app/api/v1/staff/[id]/route.ts` и `lib/catalog.ts`: ставкой
считается только число, поля независимы, пустая правка — отказ.
Проверки: `npm run smoke`, раздел про PATCH.

### S2 · Номер русскими буквами заводил вторую машину

«34АА123» кириллицей и «34AA123» латиницей выглядят посимвольно
одинаково, а для базы это разные клиенты. У мойщика с русской раскладкой
получалась вторая карточка той же машины: своя история визитов, своя
сумма, «постоянный клиент» не узнаётся при вводе, абонемент не находится.
Единственный способ заметить — сравнить коды символов.

Починено в `lib/client-key.ts`: кириллические двойники латинских букв
приводятся к латинице до сравнения. Буквы без двойников (Ж, Д, Б) не
трогаются.

**Осталось от прошлого:** записи, уже лежащие в базе с кириллицей,
остаются на месте со своей историей. Новые визиты той же машины пойдут в
латинскую карточку. Слияние старых пар — отдельная работа, здесь её нет.

### S2 · Поиск не находил то, что видно в списке

Список клиентов приводил запрос своей строчкой рядом
(`replace(/\s/g,'').toUpperCase()`) вместо общей функции. Отличий было
два: дефис не убирался, кириллица не переводилась. Номер «22 OO 145»,
набранный с русскими О, не находился — карточка была в списке, выглядела
ровно так же, как запрос, и не открывалась.

Починено в `app/owner/clients/workspace.tsx`: приведение тем же
`compactClientKey`, которым запись ложится в базу.

### S3 · Сумма больше, чем бывает, роняла сервер

Расход в триллион отвечал `500 INTERNAL`: столбцы денег `integer`, и
Postgres такую вставку не принимает. Пятисотка читается как поломка
сервера, и человек жмёт «сохранить» ещё раз вместо того, чтобы убрать
лишний ноль.

Починено: `MAX_MONEY` в `lib/money.ts`, проверка в расходах
(`lib/expenses.ts`) и в цене услуги (`lib/catalog.ts`).

### S3 · Скрипт сверки спорил с продуктом

`scripts/audit-numbers.ts` — тот самый инструмент, которым проверяют
цифры, когда им не верят, — считал долю `round`, а продукт считает
`floor`. На круглых демо-ценах разницы не видно; на живой мойке со
скидками «второе мнение» начинало спорить с правильным ответом.

Починено. Проверка теперь стоит на цифре, где два способа расходятся:
999 ֏ под 33 % — 329 вниз, 330 к ближайшему.

### S4 · Номер в 300 знаков

Принимался в базу и попадал в список клиентов и в выгрузку. Ключ клиента
не правится, то есть чинить такую строку потом нечем. Ограничение в 32
знака — номер машины это семь, телефон двенадцать.

## Осталось

**Записи без `ref` можно задвоить.** `POST /api/v1/orders` без поля `ref`
не защищён от повтора: два одинаковых запроса дают две машины. Оба
клиента продукта `ref` шлют всегда — веб генерирует его в форме,
приложение в очереди, — поэтому в жизни это недостижимо. Сделать поле
обязательным нельзя: в очередях уже выпущенных сборок лежат записи
старого вида, и они обязаны доехать.

**Кириллические карточки из прошлого.** См. выше: старые записи не
сливаются с латинскими автоматически.

**Экран мойщика говорит «смена не начата» и тут же показывает выручку
смены.** Так выглядит день, когда смену уже закрыли вечером, а записи за
день остались. Формально верно, читается противоречиво. Решение — за
владельцем продукта: это вопрос слов, а не расчёта.

**Емодзи в номере машины** принимается. Ограничение по длине поставлено,
по составу символов — нет: непонятно, где граница между «мусор» и
«внутренний номер, который завёл сам владелец».

## Чем закрыто от повторения

```bash
npm run smoke
```

Слой данных на чистой базе в памяти. Добавлено в этот прогон:

* округление доли — одно правило в смене, зарплате, дневном листе и SQL;
* потолок суммы у расхода и цены услуги;
* кириллица в номере: обе записи ложатся на одну машину;
* частичная правка человека и отказ на `null` в ставке;
* замок на чужую базу — четыре проверки отдельными процессами.

```bash
npm run e2e
```

95 проверок по живому серверу: маршруты, токены, роли, чужие правки,
подписка, доступность страниц.

```bash
npx tsx scripts/audit-numbers.ts
```

Пересчёт цифр кабинета голым SQL — второе мнение, когда числу не верят.
