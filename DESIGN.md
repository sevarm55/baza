# Дизайн-система «Панель»

Палитра взята с шестого референса — **RUNCO**.

Структура собрана из пяти: **FastFood** (стекло на фотографии), **MODISK**
(бенто с оранжевой плиткой), **American Tall** (чёрные швы, круг на стыке),
**P58** (тёплые панели над фото, капсулы и круги), **FitPulse** (мобильный:
стекло над съёмкой).

---

## 0. Что у них общего

Пять сайтов из разных индустрий, а решения одни и те же. Шесть совпадений —
это и есть система:

1. **Страница — не лента, а щит из плиток.** Прямоугольники разного размера
   упакованы плотно, шов между ними одинаковый, каждый со своим большим
   радиусом. У MODISK и American Tall это видно буквально; FastFood и
   FitPulse — та же логика при одной плитке.
2. **Пустота живёт ВНУТРИ плиток, а не между ними.** Швы узкие и постоянные,
   а внутри каждой плитки воздуха много. Это обратно обычной вёрстке, где
   между секциями сто пикселей, а внутри тесно.
3. **Фотография — содержимое, а не фон.** В каждом референсе есть настоящий
   снятый предмет: бургер, диск, бутылка, рюкзак, человек. Он либо вырезан по
   контуру, либо вылезает за край своей плитки. Абстрактных градиентов в роли
   картинки нет нигде.
4. **Поверх фотографии — прозрачный слой.** Стеклянные панели с тонкой
   светлой обводкой: интерфейс плавает над снимком, а не лежит рядом с ним.
5. **Язык управления — капсула и круг.** Капсульные кнопки, капсульные теги,
   круглые кнопки-иконки. Круг часто сидит **на шве** между двумя плитками и
   перекрывает обе. Главная кнопка везде одна и та же: текст в капсуле плюс
   круг со стрелкой вплотную к правому краю.
6. **Кеглей мало, контраст между ними огромный.** Тяжёлый гротеск капсом для
   заголовка, крошечный капс для ярлыка, обычный мелкий для текста. Третьего
   размера почти не бывает, и промежуточных нет.

Плюс приём, который делает эти щиты живыми: **одно огромное число** на
плитку — «20 hr», «20% OFF», «50%». Число работает как картинка.

## 1. Что взято откуда

| Взято | Откуда | Почему |
|---|---|---|
| Бенто-сетка с постоянным швом | MODISK, American Tall | Держит плотность без единой линейки-разделителя |
| Чёрный шов как рисунок сетки | American Tall | Самое сильное решение из пяти: сетка перестаёт быть пустотой и становится графикой |
| Круг, сидящий на шве двух плиток | American Tall | Одна деталь, которая доказывает, что сетка настоящая |
| Одна насыщенная плитка на весь щит | MODISK | Цвет как объект, а не как заливка фона |
| Вертикальный логотип вдоль края | MODISK | Держит левый край и решает, куда девать имя |
| Стекло над фотографией | FastFood, P58, FitPulse | Интерфейс поверх снимка, а не рядом |
| Вырезанный предмет, вылезающий за край | FastFood, P58 | Ломает прямоугольник, не ломая сетку |
| Капсула + круг со стрелкой | все пять | Общий знаменатель. Канон. |
| Круглые кнопки-иконки в ряд | FitPulse, P58 | Плотный набор действий без подписей |

**Что осознанно не взято:**

- Рукописный логотип FastFood — он из другой эпохи и в паре с гротеском
  читается как случайность.
- Фиолетово-розовый градиент FastFood во всю площадь: цвет, которым залито
  всё, перестаёт быть цветом.
- Три телефона в перспективе как способ показать продукт (FitPulse). Экраны
  показываем плоско, внутри плиток.
- Тонкая вертикальная линейка слева от заголовка (FastFood) — декоративная
  палка, которая ничего не разделяет.

## 2. Сетка

Щит — 12 колонок, шов постоянный, плитки занимают целое число колонок и
целое число строк.

```
макс. ширина          1440px
колонок               12
шов (gap)             clamp(8px, 0.9vw, 14px)
поле страницы         = шву: щит доходит до самого края
высота строки         clamp(96px, 11vw, 160px)
```

**Шов равен полю страницы.** Это то, из-за чего щит выглядит цельным
предметом: плитка у края отстоит от края ровно настолько же, насколько от
соседки.

Плитки ставятся по площадям, а не по колонкам-в-ряд:

```
┌──────┬───────────────────┬─────────┐
│ имя  │   заголовок       │         │
│ верт.├───────────────────┤  фото   │
│      │  акцентная плитка │  во всю │
│      │  с большим числом │  высоту │
├──────┴─────────┬─────────┤         │
│  мелкая плитка │  список │         │
└────────────────┴─────────┴─────────┘
```

Правило: **на щите не больше одной плитки каждого размера подряд.** Четыре
одинаковых прямоугольника в ряд — это не бенто, а таблица.

## 3. Плитки

```css
--r-tile:  clamp(16px, 1.6vw, 26px);   /* плитка */
--r-inner: calc(var(--r-tile) - 8px);  /* фото и поля внутри плитки */
--r-pill:  999px;                      /* всё нажимаемое */
--seam:    clamp(8px, 0.9vw, 14px);
```

Внутренний радиус = внешний минус отступ. Плитка с 26 и падингом 8 содержит
картинку с 18. Иначе углы «плывут» — по этому сразу видно любительскую руку.

**Падинг внутри плитки** — `clamp(20px, 2.2vw, 34px)`. Он больше шва в
два-три раза: воздух живёт внутри.

**Тени нет ни одной.** Плитки разделены швом и цветом. Тень под плиткой в
бенто — признак того, что сетке не доверяют.

**Обводка** — только на стеклянных плитках, 1px. На сплошных не бывает.

## 4. Цвет

Взято с референса RUNCO: тёмный там только шов, а плитки цветные. Чистый
чёрный на площади страницы читается дырой и делает всё вокруг мрачным,
поэтому его нет вовсе.

```css
:root {
  /* шов и тёмная плитка */
  --ground:   #1c1c1e;  /* цвет шва: тёплый уголь, не чёрный */
  --charcoal: #2a2a2c;  /* тёмная плитка */

  /* цветные плитки */
  --mint:     #c8dcd1;  /* держит первый экран */
  --violet:   #7e7ceb;  /* приложение, деньги исполнителя */
  --tile:     #f5f4f1;  /* нейтральная светлая */
  --paper:    #ffffff;  /* плитка под экраном продукта */

  /* действие */
  --lime:     #c9f24d;
  --lime-ink: #14200a;

  --ink:      #141416;
  --muted:    rgb(20 20 22 / 0.6);
  --faint:    rgb(20 20 22 / 0.44);

  --glass:      rgb(255 255 255 / 0.14);
  --glass-line: rgb(255 255 255 / 0.26);
  --on-dark:    rgb(255 255 255 / 0.74);
}
```

**Пропорция на щит: 40 цветных плиток / 30 фотографии / 20 светлых
нейтральных / 8 угля / 2 лайма.**

**Правила:**

- **Лайм принадлежит только действию.** Кнопка, круг на шве, одна плитка с
  числом на щит. Второе лаймовое пятно рядом обесценивает первое; поэтому
  заработок внутри экрана продукта — сиреневый, а не лаймовый.
- **Уголь — это шов и максимум одна плитка на щит.** Больше — и щит
  становится тёмной темой, а не светлой страницей с тёмными акцентами.
- **Мята и сирень не соседствуют через шов.** Между ними всегда светлая,
  угольная или фотоплитка: два насыщенных цвета встык дребезжат.
- Текст на мяте — `--ink`. Текст на сирени и угле — белый. Текст на лайме —
  `--lime-ink`, тёмно-зелёный: чистый чёрный на кислотном вибрирует.
- Цвет плитки выбирается по роли, а не по очереди: мята — заявление,
  сирень — продукт и деньги, уголь — служебное, лайм — действие.

## 5. Типографика

Одна тяжёлая гротеска. Второй шрифт не нужен и всё испортит.

- **Латиница и цифры:** Archivo (700/800) — плотная, широкая, хорошо стоит в
  капсе и в больших числах.
- **Армянский:** Mardoto Bold — единственная гарнитура в проекте,
  нарисованная под этот алфавит. У латинских дисплейных шрифтов армянских
  глифов нет, и подстановка развалит систему.

```css
--font-display: 'Archivo', 'Mardoto', system-ui, sans-serif;
--font-ui:      'Mardoto', 'Archivo', system-ui, sans-serif;
```

### Шкала

Четыре размера. Больше не нужно.

| Роль | Размер | Насыщ. | Трекинг | Интерлиньяж | Регистр |
|---|---|---|---|---|---|
| `figure` — одно большое число | `clamp(64px, 9vw, 148px)` | 800 | −0.04em | 0.84 | — |
| `head` — заголовок плитки | `clamp(24px, 2.6vw, 42px)` | 700 | −0.02em | 1.04 | КАПС |
| `body` | 15–16px | 400 | 0 | 1.55 | обычный |
| `tag` — ярлык и капсула | 10.5px | 700 | +0.12em | 1.2 | КАПС |

**Правила:**

1. Заголовок плитки — капс. Армянский капс читается хуже латинского, поэтому
   для длинных армянских фраз регистр обычный, а вес остаётся 700.
2. Между `head` и `body` нет промежуточного кегля. Захотелось «чуть крупнее» —
   значит, это `head` в маленькой плитке.
3. `figure` в плитке одна. Второе большое число рядом убивает первое.
4. Абзац не шире 58 символов.
5. Вертикальный логотип вдоль левого края: `writing-mode: vertical-rl;
   transform: rotate(180deg)`, кегль как у `head`, трекинг −0.03em.

## 6. Фотография

Это единственное, чего в системе нельзя подделать градиентом.

**Три роли снимка:**

1. **Плитка целиком** — фото заполняет плитку, `object-fit: cover`, предмет
   смещён от центра, чтобы часть его уходила под соседнюю плитку.
2. **Вырез без фона** — предмет вырезан по контуру и лежит поверх плитки,
   вылезая за её край на 8–15% высоты. Ломает прямоугольник, не ломая сетку.
3. **Задник под стеклом** — снимок в полную плитку, поверх него стеклянная
   панель с текстом.

**Что снимаем: руки за работой.** Продукт продаётся автомойкам, но устроен
под шесть ниш, и дальше их будет больше. Отраслевой кадр придётся менять на
каждой новой нише — руки не придётся. Мойщик, барбер, механик, клинер, врач:
все делают что-то руками для клиента и все записывают это в телефон. Рука с
телефоном показывает не отрасль, а сам механизм продукта.

Крупный кроп по запястье, кисть заполняет кадр, предмет в рабочем хвате. Ни
лиц, ни тел, ни второй руки. Ни одной машины на витрине.

**Как готовим:**

- Кадр снимается под цвет плитки, а не под чёрный фон. Два режима:
  **вырез на плоской мяте** `#C8DCD1` (предмет целиком, без пола, тени и
  отражения) и **высветленный крупный план** без тёмных углов.
- Свет мягкий и ровный, один деликатный блик. Жёсткая тень уводит кадр в
  прежний мрачный мир.
- Фон под вырез абсолютно однородный, без градиента: иначе плитка выдаёт
  прямоугольник.
- Цвет приводится к палитре: холодный нейтральный или мятный, без
  посторонних тёплых пятен, чтобы лайм остался единственным горячим местом.

**Подпись на снимке — по свету кадра.** На тёмном снимке стекло с белым
текстом и затемнением под ним. На светлом стекло не работает: белый текст
пропадает, а затемнять высветленный кадр значит его испортить — там плотная
светлая карточка с тёмным текстом. Правило одно: подпись читается на самом
ярком участке снимка.

**Генерация.** Промпт всегда называет: предмет, материал, свет, фон, ракурс.
Для выреза добавляется `completely flat pale sage mint #C8DCD1 background,
absolutely uniform, no floor, no horizon, no cast shadow, no reflection`.
Каждая сгенерированная картинка кладётся в `public/shots/` и помечается в
`public/shots/README.md` как синтетическая — на странице она иллюстрация, а
не доказательство. Отзывы, логотипы клиентов и цифры «N моек уже считают»
генерировать нельзя ни в каком виде.

## 7. Стекло

Стекло применяется **только поверх фотографии**. На сплошной плитке размывать
нечего, и оно превращается в мутную плашку.

```css
.glass {
  border-radius: var(--r-tile);
  border: 1px solid var(--glass-line);
  background: var(--glass);
  backdrop-filter: blur(28px) saturate(140%);
  -webkit-backdrop-filter: blur(28px) saturate(140%);
  color: var(--paper);
}
```

Под стеклом текст всегда белый, и под ним обязателен затемняющий слой
`linear-gradient(rgb(0 0 0 / 0.35), rgb(0 0 0 / 0.55))` — иначе на светлом
участке снимка подпись пропадает.

## 8. Управление

### Кнопка — канон

Текст в капсуле плюс круг со значком вплотную к правому краю.

```
[  Փորձել 6 օր անվճար   (↗) ]
```

- Высота 56 (крупная) / 44 (обычная), падинг `0 8px 0 26px`, круг 40.
- **Primary:** заливка `--accent`, текст белый, круг чёрный со стрелкой цвета
  акцента.
- **Secondary:** заливка `--tile`, текст `--ink`, круг чёрный.
- **On glass:** прозрачная, обводка `--glass-line`, текст белый.
- Ховер: `translateY(-2px)`, круг доворачивается на 45°.

### Круглая кнопка

40 или 48, только значок, обводка 1px или заливка. Ставятся по 2–4 в ряд с
шагом 6px. Подписей нет — если нужна подпись, это капсула, а не круг.

### Круг на шве

Круг 56–72, лежит ровно на стыке двух плиток и перекрывает обе. Обводка
цветом шва толщиной `--seam`, чтобы он читался как вырез в сетке, а не как
наклейка. **Один на щит.**

```css
.seamButton {
  position: absolute;
  width: 64px;
  height: 64px;
  border-radius: var(--r-pill);
  box-shadow: 0 0 0 var(--seam) var(--ground);
}
```

### Тег

Капсула, обводка 1px, текст `tag`. Идут группой по 3–5, переносятся строкой.

## 9. Ритм щита

Секция — это щит. Между щитами тот же шов, что и между плитками, так что
страница читается одним полотном.

```
щит 1  ЛИЦО      имя вертикально · заголовок · акцентная плитка с числом · фото во всю высоту
щит 2  РАБОТА    экран продукта в белой плитке 8 колонок · рядом две мелких с фактами
щит 3  СНИМОК    одна фотоплитка во всю ширину, стекло с одной фразой
щит 4  ПОДРОБНО  четыре разных по размеру плитки: список, число, вырез, текст
щит 5  ЦЕНА      акцентная плитка во всю ширину, одно число, одна кнопка
подвал           чёрная плитка, вертикальный логотип, капсульные ссылки
```

Правило: **два соседних щита не могут иметь одинаковую раскладку.**

## 10. Мобильный

Из FitPulse: тёмный низ, съёмка сверху, стекло поверх.

- Щит разворачивается в один столбец, шов остаётся тем же.
- Порядок внутри щита задаётся явно, а не наследуется от десктопа: первой
  идёт та плитка, ради которой щит существует.
- Акцентная плитка не переносится вниз: она должна попасть в первый экран.
- Фотоплитка становится высотой `62svh` и уходит под первую стеклянную
  карточку.
- Стеклянные карточки прижимаются к низу экрана с отступом `16px`, чтобы
  большой палец до них доставал.
- Круглые кнопки — минимум 44×44, между ними не меньше 8.
- Вертикальный логотип на мобильном разворачивается в горизонтальный: на
  360 пикселях он съедает всю высоту.

## 11. Движение

```css
--ease:  cubic-bezier(0.2, 0, 0, 1);
--slow:  cubic-bezier(0.16, 1, 0.3, 1);
--t-micro: 160ms;
--t-tile:  420ms;
```

- Плитки въезжают **по щиту, а не по одной**: весь щит поднимается на 16px и
  проявляется, задержка между щитами 60ms. Отдельная анимация у каждой плитки
  превращает страницу в мигающую гирлянду.
- Фото внутри плитки на ховере — `scale(1.03)`, 600ms, плитка не двигается.
- Круг на шве вращается на 90° при наведении.
- Большое число не считается вверх на скролле. Это не счётчик, это факт.
- `prefers-reduced-motion`: остаётся только прозрачность.

### 11.1. Длительности — одни на три клиента

Числа лежат в трёх файлах и правятся вместе: `lib/motion.ts`,
`ios/Tetr/Design/Motion.swift`, `android/…/design/Motion.kt`. Продукт один, и
человек, который утром смотрит выручку в браузере, а днём записывает машину с
телефона, не должен замечать, что переходы там и тут разной длины.

| имя       | мс   | работа                                    |
|-----------|------|-------------------------------------------|
| `instant` | 110  | нажатие, отклик под пальцем               |
| `fast`    | 170  | смена состояния мелкой детали             |
| `normal`  | 240  | приход содержимого, перекрёстное затухание |
| `slow`    | 450  | перестроение фигуры, морф                 |
| оборот загрузчика | 1350 | полный цикл фирменной фигуры       |

Пружины: `springSoft` (260 / 0.82) возит крупное, `springSnap` (340 / 0.72)
возит мелкое. Одну кривую на всё не берём: морф с той же кривой, что нажатие,
выглядит дёрганым, а нажатие с кривой морфа — вязким.

### 11.2. Пять уровней ожидания

Смешивать их нельзя. Уровень выбирается по тому, **что именно** ждёт, а не по
тому, сколько это займёт.

| уровень | когда | чем показан |
|---|---|---|
| A · приложение | запуск, восстановление сессии | заставка с `TetrinLoader` |
| B · страница | первая загрузка раздела | скелет **по форме этой страницы** |
| C · часть | ждёт один прибор | скелет внутри прибора, остальное живо |
| D · действие | нажали кнопку | кнопка занята, геометрия не меняется |
| E · фон | данные есть, идёт сверка | точка у заголовка, содержимое на месте |

Заслонка на весь экран допустима только на уровне A. На вебе такого повода
нет вовсе: оболочка кабинета приезжает собранной с сервера.

### 11.3. Фирменный загрузчик

Четыре лаймовых столбика, оборот 1.35 с:

```
волна → сходятся → складываются 2×2 → вдох → расходятся
```

Ни один кадр не крутится вокруг центра: вращение — чужой язык, и фигура,
которая крутится, перестаёт быть чьей-то. Оборот кончается там же, где
начался, поэтому шва между оборотами не видно.

Внутри кнопок стоит малый загрузчик — три детали, только волна, без морфа:
кнопку «записать» жмут сорок раз за смену, и фигура, которая на каждое
нажатие собирается в квадрат, через неделю начинает раздражать. Праздник на
запуске, в работе достаточно признака жизни.

### 11.4. Порог показа

Загрузка получает право показаться через **180 мс** (в кнопке через 90).
Запрос на девяносто миллисекунд, отмеченный скелетом, выглядит хуже, чем тот
же запрос без ничего: человек видит вспышку серого и считает, что экран
дрогнул. Готовый ответ при этом никогда не придерживаем: порог откладывает
показ загрузки, а не показ данных, и «замедлить ради анимации» запрещено.

### 11.5. Занято ≠ погашено

Погашенная кнопка говорит «сейчас нельзя», занятая — «принято, идёт». Это
разные сообщения, и выглядеть они обязаны по-разному: погашенная бледнеет,
занятая остаётся в полном цвете и называет, что делает («Պահպանվում է…»).
Ширина кнопки при этом не меняется никогда: подписи лежат стопкой в одной
ячейке, и кнопка равна самой длинной из них.

## 12. Проверка перед сдачей

- [ ] Шов одинаковый везде и равен полю страницы.
- [ ] Внутренний радиус = внешний минус отступ.
- [ ] Падинг внутри плитки больше шва минимум вдвое.
- [ ] Лаймовая плитка на щите ровно одна, и лайм больше нигде, кроме кнопок.
- [ ] Ни одной тени под плитками.
- [ ] Обводка только на стекле.
- [ ] Стекло только поверх фотографии, и под текстом есть затемнение.
- [ ] Одно большое число на плитку.
- [ ] Мята и сирень нигде не встык.
- [ ] Чистого чёрного на странице нет ни пикселя.
- [ ] Кеглей на странице четыре, а не восемь.
- [ ] На щите нет четырёх одинаковых плиток подряд.
- [ ] Два соседних щита раскладкой не совпадают.
- [ ] Круг на шве один на щит.
- [ ] Каждая сгенерированная картинка отмечена в `public/shots/README.md`.
- [ ] Контраст текста ≥ 4.5:1, на стекле проверен на самом светлом участке
      снимка.
- [ ] Проверено при `prefers-reduced-motion: reduce`.
- [ ] Пусто, «не доехало» и «идёт» на экране — три разных ответа, а не один.
- [ ] Погашенная и занятая кнопка выглядят по-разному.
- [ ] Ширина кнопки не меняется, когда она становится занятой.
- [ ] Быстрый ответ не мигает скелетом (порог 180 мс).
- [ ] Обычное обновление не убирает с экрана уже показанные данные.
- [ ] Скелет раздела повторяет форму именно этого раздела.
- [ ] После отказа виден повтор, а не вечный загрузчик.
